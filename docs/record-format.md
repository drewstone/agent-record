# Record format

The schema and TypeScript types are exported from `@drewstone/agent-record/record` without importing React.
This is a display contract, not an execution protocol or a lossless universal log format.
Keep original archives separately.

```ts
import { parseRecord } from '@drewstone/agent-record/record'

const record = parseRecord({
  schema: 'agent-record.v1',
  runId: 'run-123',
  title: 'A recorded task',
  nodes: [{
    id: 'agent-1', kind: 'agent', label: 'Director', parent: null,
    role: 'Director', assignment: 'Review the supplied findings',
  }],
  events: [{
    id: 'message-1', node: 'agent-1', at: '2026-10-02T09:00:00Z',
    kind: 'message', category: 'coordination', label: 'Assignment',
    source: { path: 'session.jsonl', line: 1 },
    detail: { role: 'user', publicText: 'Review the supplied findings.' },
  }],
})
```

This small example illustrates the format; the runnable example uses actual retained research data.
Sources, assignment context, terminal state, and capture coverage may be omitted when unavailable.
Validation supplies empty context and explicitly unknown coverage, never invented evidence.
Timestamps must be ISO 8601 with `Z` or an explicit offset.
The viewer displays clock times in UTC and retains the original strings.

## Nodes

`kind` is `agent`, `session`, or `finding`.
Use a distinct session node for each native harness session.
Only set `agentId` when the importer has evidence that this session belongs to that agent.
Store that evidence in `joinBasis` and `joinProof`.
A session ID by itself does not establish a parent relationship.

`parent` describes the recorded delegation relationship.
`role` and `assignment` are display descriptions, not permissions or claims of competence.
`model` records configuration; `servedModel` records response identity where available.
The converter sets `servedModel` only on a node with at least one successful assistant response; a materialization receipt or profile fills `model`, never `servedModel`.
`modelSource` can describe that identity's provenance.
`start`, `end`, and `status` describe observed lifecycle state.
Unknown lifecycle values remain unknown.

## Events and tool pairs

Every event has a unique ID within its run and references an existing node.
The array order is retained separately from timestamp order.
Event `detail` preserves additional producer metadata.
`publicText` is text the host has explicitly chosen to display, not an automatic privacy review.
The viewer renders it as escaped text.

Tool calls use:

```ts
{
  role: 'assistant',
  publicToolCalls: [{ id: 'call-1', name: 'read', input: '{"path":"report.md"}' }],
}
```

A result in the **same original node** uses:

```ts
{
  role: 'toolResult', toolCallId: 'call-1',
  publicText: 'Retained output text', isError: false,
}
```

`input` is a displayable string, often a command or formatted JSON.
Several result events can share a call ID.
Several distinct calls in the same session sharing an ID are ambiguous and stay unpaired.
Call IDs may be reused in other sessions or runs.
The viewer does not pair them across those boundaries.

`isError: false` means the producer did not mark the result as an error.
It does not certify that a shell pipeline or scientific claim succeeded.
Missing arguments, results, bodies, and usage are not generated by the viewer.

`publicationNote` should describe a redaction or excerpt where applicable.
Do not send secrets to a public page, including in source metadata or hidden tabs.
The component's download includes the entire supplied record.

## Usage and categories

Optional `detail.usage` fields are `input`, `output`, `cacheRead`, and `cacheWrite`.
They are nonnegative recorded counters, not a billing calculation.
Partial measurements remain partial.
Do not infer billed cost or unique text from repeated context counters.

Categories are producer annotations.
The built-in palette recognizes coordination, computation, verification, literature, infrastructure, and other.
Additional category strings remain available for filtering.
No category establishes research value, independence, or waste.

## Source and coverage

An event source can contain `path`, optional SHA-256 `sha256`, and optional positive physical `line`.
The source object can retain additional metadata.
Omit a source when unavailable; never fabricate an archive location.

`coverage` can describe `completeOriginalCapture`, `publicContent`, `categoryMethod`, and `cost`.
The completeness flag is an assertion from the producer, not an attestation performed by the viewer.
The converter asserts it only when the record has agent or session nodes and every one has a complete capture; finding pages alone never make a capture complete.
Missing cost is unknown: the converter writes `Not recorded` unless an event carries `costListUsd`.
Historical corrections should remain source-linked, not silently replace original records.

## Optional fields added in 0.4

Nodes can carry `harness`, `sandboxes` (execution environment IDs in first-seen order) and `capture`:
`{channel, status: complete | lossy | absent, reason}`, the channel the conversation came from and why it is incomplete.

Event `detail` can carry:

| Field | Meaning |
| --- | --- |
| `reasoning` | Reasoning text the harness recorded. |
| `reasoningOmitted` | Thinking blocks the provider returned without text (signature only). The model thought; no text exists to show. |
| `reasoningRedacted` | Encrypted `redacted_thinking` blocks. |
| `durationMs` | Tool call to result time from the source's own clock. |
| `costListUsd`, `usdKnown` | List-price estimate from recorded usage. `usdKnown: false` means no bill confirms it. |
| `rateLimit` | `{window, utilization, status}` from a provider rate-limit event. |
| `clip` | `{bytes, sha256}`: the body was shortened to the first three quarters and last quarter of the size limit. `sha256` names the `sources` entry with the full text, or is null when no single source holds it. |

A `sources` entry can locate bytes inside a file with `line` (one physical line) or `pointer` (a JSON Pointer).
Its `sha256` and `bytes` then cover exactly those bytes: the line without its newline, or the resolved value (a string's UTF-8 bytes, otherwise its JSON text).
Without `line` or `pointer` they cover the whole file.
`coverage.nodes` lists each node's capture and `coverage.gaps` lists `{nodeId, code, detail}` for evidence that is missing.

## Agent-runtime run directories and bundles

`@drewstone/agent-record/adapters/agent-runtime` converts one agent-runtime run directory, or one bundle directory (Node only):

```sh
node tools/ingest.mjs <dir> --out record.json [--run-id <id>] [--manifest <snapshot.json>] [--native <dir>] [--max-text 16384]
# writes record.json and record.json.gz and prints
# {"runId", "recordDigest", "bytes", "nodes", "events", "coverage": {"complete", "lossy", "absent"}}
```

It reads only the directory and the optional `--native` cache, writes nothing into either and makes no network requests.
The same inputs and adapter version produce identical bytes; `recordDigest` is the SHA-256 of the JSON.
With `--manifest` (an `evidence.snapshot.v1` file list from the evidence store) the directory must hold exactly the listed files with their SHA-256 and length, or nothing is converted; the record names the manifest digest in `input.snapshot`.
The run ID comes from `--run-id`, then the manifest's `runId`, then the directory name; `input.runIdBasis` says which.
The record depends on files only, never on empty directories, which a snapshot does not hold: an archive extraction and the same snapshot materialized from the store convert to the same bytes.
Exit code 2 means the directory is unreadable; 3 means the record would exceed 128 MiB; 4 means the directory differs from its manifest or two events claim one anchor.

Every `spawned` ID in `spawn-journal.jsonl` is an agent node, and its parent is the ID without its last `:sN` segment.
Each node's conversation comes from the first channel that holds it:

0. `live`: only while the node has not settled, its Sandbox session events recorded so far, one JSON line per event under `evidence/live-stream/<encodeURIComponent(node id)>/`. The final state of each part id is shown, as for `part` below. Once the node settles its native session is read instead, so a turn is never shown from both.
1. `native`: each Claude Code main session file, read from its longest stored copy. A session file is append-only, so every copy is a prefix of the same bytes. The copies are:
   - a retained harness transcript archive, extracted under `--native/<64-hex archive digest>/` and checked against the manifest's SHA-256;
   - the node's latest capture in `evidence/native-index.jsonl` (`disco.native-capture.v1`), whose archive is extracted under the same cache.
2. `oc`: OpenCode `native-trajectory.json`.
3. `pi`: `trace/pi-sessions/**`, joined to the node whose spawned task digest equals the SHA-256 of the session's first user text as a JSON string.
4. `bridge`: a retained cli-bridge export under `trace/bridge-sessions/`, joined to the node whose `materialized` receipt names the bridge session ID.
5. `part`: the node's output blobs, collapsed to the final state of each part ID; Codex command items and Kimi tool results included.
6. `root`: `root-stream.jsonl` for the root; text and reasoning deltas collapse into one block per turn, and a resumed attempt's replay of its predecessor is dropped (reported as a gap).
7. `journal`: lifecycle events only.

The other channels are listed in `sources` and never repeated as events.
Every timestamped line of a session, journal or stream becomes exactly one event, or one per item when a line carries several (tool results, tool calls).
A line the converter does not interpret (a Pi session header, a model or thinking-level change, a custom entry, a Claude Code attachment or system line, a stream status row) is a `record` event carrying its type.
Untimed and unparsable lines are counted in `coverage.gaps`.
A Pi session whose tool call has no result line is a `lossy` capture (`tool-results-not-retained`), as a root stream is.
A Pi message also carries `nativeParentId`, `contentSha256` and `contentCharacters` (the earlier publication converter's digest of its content and the length of its text or thinking), and an assistant message its `responseReportedModel`, `responseStatus` (the stop reason) and `responseId`.
Line files are split and decoded one line at a time, so a session larger than the longest JavaScript string still converts; lines outside a bundle's `lines` window are not decoded.

Every `kb/pages/**/*.md` page becomes one `finding-record` event on node `finding:<runId>`, with the frontmatter `title` and `createdAt` and the page body as `detail.recordedClaim`.
A page without `createdAt` (a `RESULT.md`) takes the modification time its snapshot manifest recorded, with `detail.atBasis: "snapshot-mtime"`; without a manifest time it is a `finding-untimed` gap.
A directory with knowledge pages and no run files has format `finding-only`.

### Event IDs (`idScheme: "anchor.v1"`)

An event ID names the stored bytes it came from: `<o>:<loc>[.<k>]`.
`o` is the first 12 hex digits of the SHA-256 of the whole source file; `loc` is the 1-based physical line (split on LF) of a line file, or the JSON Pointer into a JSON document; `k` is the item's index in the source's own content array when one line or item yields several events (a tool call and its result are items 0 and 1 of one tool part).
A whole-page event is `<o>` alone, and a collapsed run of stream deltas takes its first line's anchor with `detail.anchorRange`.
Each event's `source` carries the same `sha256`, `line` or `pointer`, and `item`, so anyone can recompute the ID from the object alone.
The ID holds no node ID, channel, position or suffix: a new join, a channel choice or a converter release moves events between nodes without changing an ID.
A repeated anchor is an error, and a 12-digit prefix names exactly one object among the record's sources.
Native record IDs (Claude Code `uuid`, Pi `id`, part IDs, stream `seq`) stay in `detail.nativeRecordId`.

`@drewstone/agent-record/publication` exports `anchorId`, `parseAnchor`, `checkAnchors` (every ID recomputed from its object, which the caller supplies as bytes), `buildIdMap` (earlier IDs to the event holding the same bytes, ambiguous ones reported), `sourceBytes`, and the `evidence.snapshot.v1` and `agent-record.bundle.v1` schemas.

### Bundles

A directory with a `bundle.json` (`agent-record.bundle.v1`) is one record from several sources; every path is relative to the bundle root:

```json
{
  "schema": "agent-record.bundle.v1",
  "recordId": "wf_3b2a5d92-078",
  "sessions": [{ "path": "subagents/workflows/wf_3b2a5d92-078/agent-a94104781fd274f5e.jsonl", "harness": "claude-code" }],
  "journals": [{ "path": "subagents/workflows/wf_3b2a5d92-078/journal.jsonl", "kind": "claude-workflow", "workflow": "workflows/wf_3b2a5d92-078.json" }],
  "runs": [{ "path": "lab-run/subscription-apn-glm-lab-20260927c", "kind": "agent-runtime" }],
  "findings": [{ "path": "kb/pages" }]
}
```

`harness` is `claude-code`, `codex`, `opencode`, `opencode-bridge` or `pi`; `lines` (`[[from, to], ...]`, inclusive) limits a long session to the window the record is about.
Joins come from evidence only, and each node records `joinBasis` and `joinProof`:
`workflow-agent-id` when a workflow journal's agent ID is the one carried by `agent-<id>.jsonl` beside `agent-<id>.meta.json`, and `session-directory` when a session or journal sits under `<parent session id>/subagents/` of its declared `parentPath`.
A join that does not verify leaves the session as its own node and adds a gap.
Workflow journal rows carry no time; a `started` row takes its session's first event time and a `result` row its last (`detail.atBasis`).

## Workspace and assessment documents

`@drewstone/agent-record/workspace` and `@drewstone/agent-record/assessment` export Zod schemas for the run workspace API: `agent-workspace.plays.v1`, `agent-workspace.play.v1`, `agent-workspace.run.v1`, `agent-trace-dimensions.v1`, `agent-trace-assessment.v1` rows and `agent-trace-assessments.v1`.
JSON Schema for each, and for `agent-record.v1`, ships in `dist/schemas/`.
Unknown dollar amounts are `null` and never count as zero.
